# Bloco pós-F2: plano de implementação


> **Para quem executa:** use `superpowers:subagent-driven-development` nas tarefas CRÍTICAS e `superpowers:executing-plans` nas demais, com `superpowers:test-driven-development` em todas. Passos com caixa (`- [ ]`). Nunca commitar sem o Luís pedir; o último passo de cada tarefa é sugerir o commit.

**Goal:** fechar as pendências pós-F2 para a F3 começar com entrada no painel, `Origin`, rotas por sessão, lint e E2E resolvidos.

**Architecture:** uma função pura no core (`classifyPanelEntry`) decide a entrada; o `AuthStore` a alimenta; o login e um `checkEntry` novo a consultam. O modo restrito é um estado de sessão sem `PanelContext`, servido por um grupo de rotas próprio no web. `Origin` é um hook `onRequest` na raiz do Fastify.

**Tech Stack:** TypeScript strict, Fastify, Better Auth 1.7.18, Drizzle, Next 16.4.3 (App Router, `cacheComponents`), Vitest, Testcontainers, Playwright, Biome. Nenhuma dependência nova. Nenhuma migration.

**Spec:** `docs/superpowers/specs/2026-11-11-pos-f2-design.md`

## Global Constraints

- RF02.R1: e-mail desconhecido, sem vínculo ativo ou com credencial errada recebe resposta idêntica; `NO_ACTIVE_UNIT` só depois de código ou senha certos.
- RF02.CA10: dono sem unidade vê o modo restrito com "Criar outra empresa"; gerente é recusado com a orientação.
- RNF02: sessão restrita não alcança nenhuma rota de tenant.
- Regra 9 do `CLAUDE.md`: não logar e-mail, nome, cookie nem `X-Context`.
- Erro da API só com `{ code }` (`.claude/rules/rota-de-tenant.md`).
- Códigos fixos: `NO_ACTIVE_UNIT` (403, login), `origin_forbidden` (403, hook).
- Textos fixos (pt-BR): os três da seção A6.
- Biome só nos arquivos tocados; testes com nomes em português; teste de assunto novo atualiza `.claude/dicionario-testes.md`.
